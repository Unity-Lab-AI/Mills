# Mills

A private workspace for a small team: talk to Claude in the browser and have it build and edit files on your own PC, and talk to each other in an end-to-end encrypted chat room. There's nothing to install on your side.

**Web app:** https://unity-lab-ai.github.io/Mills/ (deployed from `main` by GitHub Actions). Everyone uses the same address and signs in with **username + password**.

Accounts are created by an admin (see Accounts). The default account is `mills`; accounts flagged `admin` get an extra **Admin** section.

After signing in you land on the **main menu**: your username in the middle, and the **Work** and **Chat** buttons (plus **Admin** for admin accounts only). Every section has a **← Menu** button at the top left.

## How it works

```
Browser (GitHub Pages UI) ──username+password──▶ Cloudflare tunnel ──▶ Mills hub on the host PC (one process, every account)
   │  Work: holds the folder they opened on their PC                         ├─ runs Claude Code (the host's account) in the Mills folder, per account
   │  Chat: encrypts/decrypts messages locally                               ├─ relays Claude's file edits to that person's browser
   ◀── file edits (list/read/write/delete/mkdir) applied in the browser      └─ stores chat ciphertext only
```

## Host: running it

1. Double-click **`bridge/start.bat`** and leave the window open. One window serves every account.
   - The first time, it asks for the `mills` account password if none is set.
   - It starts a Cloudflare tunnel and posts the address to the `Mills bridge address` gist on the GitHub account `gh` is logged in to, where the web app finds it automatically.
2. Requires Node.js, Claude Code (logged in), `gh` (logged in), and `cloudflared` (path set in `bridge/config.json`).
3. Restarting is safe: passwords live in `auth.json` files and are only written by `set-password.js` or the Admin section; device locks live in each account's `state.json`; sign-in sessions live in `bridge/hub-state.json`. Nobody is signed out or asked for a new password when the hub restarts.
4. **What Claude may run.** `allowedTools` in `bridge/config.json` is the complete list of tools a Work run may use without asking (a web session cannot answer a permission prompt, so anything not listed is refused as "requires approval"). Besides reading / editing files it allows exactly the commands the worktree workflow needs: `git status / diff / log / add / commit`, the regression suite (`node bridge/test/regress.js …`) and the worktree tool (`node bridge/worktree.js …`, which also pushes develop). Nothing else runs in a shell. Unity in the chat room never gets any of these. Changing the list takes effect after a hub restart.
5. The models offered in the Work model dropdown come from `models` in `bridge/config.json` (`id` = what `claude --model` accepts, `label` = what the person sees).

### Restarts after code or config changes (Claude does this itself)

The window runs `bridge/run.js`, a small supervisor that owns the Cloudflare tunnel and runs `bridge/server.js` (the hub) underneath it. After Claude changes hub code or config it runs:

```
node bridge/restart.js
```

The hub restarts itself the moment nobody has a Claude reply in progress, under the same tunnel, so the address does not change and the web app shows "Mills is restarting" for a second and carries on. `node bridge/restart.js --hard` closes the window and relaunches `start.bat` (new tunnel address, found again automatically) for a wedged hub; `--hard --delay 30` does that 30 s later from a detached helper so the Claude run that asked for it can finish its reply; `--stop` closes it without relaunching. Progress of a hard restart is written to `bridge/restart.log`. Admins can also press **Restart hub** in the Admin section.

### Accounts

Admins manage accounts from **Admin** in the web app: create an account (a 20-character password is generated and shown once), give someone a new password, reset a device lock, sign someone out, stop their Claude run, delete an account (its folder moves to `bridge/profiles-deleted/`, nothing is destroyed). Admin can also clear the chat history.

On disk, the `mills` account is `bridge/auth.json` + `bridge/state.json` + `Mills/Archive/`; every other account is `bridge/profiles/<name>/` (`config.json`: `{ "user": "<display name>", "admin": true|false, "model": "<default model>" }`; the whole `bridge/profiles/` folder is gitignored, so names, admin flags and password hashes never leave the host) + `Mills/Archive/<name>/`. From the command line: `node bridge/set-password.js --profile <name> "password"` (no `--profile` = the `mills` account). `node bridge/master-logins.js` gives every account a new generated password and writes the whole list (username, password, display name, admin) to `Mills-master-logins.txt` on the host's Desktop — outside the Mills folder on purpose, so Claude runs in the hub never see it; device locks and sign-ins are untouched. An account whose `config.json` goes missing keeps signing in with its password (display name = username, not admin) and the hub window prints a warning, so recreate the file to restore it. Everything in `bridge/config.json` applies to every account unless the account's own `config.json` overrides it; an account's `model` is what the Work dropdown's "Default" option means.

## Using it

1. Open https://unity-lab-ai.github.io/Mills/ in **Chrome or Edge** (on Linux: Chrome, Chromium or Brave; Firefox cannot open folders) and sign in with your username and password.
2. **Work** is the Claude workspace. Click **Open folder on my PC** and pick the folder Claude should work in, then chat with Claude. It creates and edits files in that folder, and you can edit them yourself in the editor panel.
   - **Layout.** The bar on the far left (☰ widens it to show labels) has a button per panel: **Folder**, **Editor**, **Claude**, **Team chat**, plus **Settings**. Each button shows or minimizes its panel; every panel also has a **—** minimize button. Drag the thin separators between panels to resize them. **Team chat** opens the chat room inside Work, next to Claude; **Pop out** turns it into a window you can drag by its title bar and resize from its corner, **Dock** puts it back. The layout is remembered per account in that browser.
   - The message box never locks: while Claude is replying, **Queue** lines a message up for right after this reply (queued messages show dashed; ✕ removes one), and the second button is **Stop** when the box is empty or **Send now** when it has text, which stops the current reply and sends your text immediately, ahead of the queue.
   - **Sharing your Work session.** The **📡** selector above the Claude messages shares your session with **# Everyone** or one person (pick **Not shared** to stop; signing out stops it too). Everyone in that conversation gets a pop-up and a **Join work** button in the chat, which opens a **watch-only window** of your session: your Claude conversation as it happens (from the last ~150 entries when you started sharing), **what you are typing, live**, what you send and what is **queued**, and a dot that pulses while your Claude is working. Watchers cannot type into your session. Each person still works in their own session and their own worktree; open several watch windows to follow several people (drag them anywhere, ✕ to close). **Summaries:** while you have watch windows open, every message you send to your own Claude gets a short automatic summary of those sessions appended (the latest few exchanges of each, clearly marked as context, not shown in your chat and not shown to anyone watching you), so your Claude knows what the others are doing.
   - **Usage bar** (just above the Claude messages). **5h** shows how long until the current 5-hour usage window resets (hh:mm:ss), **7d** the weekly window (dd hh mm), each with a small fill bar. These limits belong to the host's single Claude account, so everyone shares them. Claude Code reports exact numbers (percentage used + reset time) once usage gets noticeable; until then the windows are estimated from when Mills started using Claude and marked "est". **Context** is how full this session's context window is (tokens used of the model's window): the bar slides from green through orange and yellow to red as it fills, and turns purple when you are out of usage (context full, or the account hit its limit) — start a **New chat** then. Hover any part for details.
   - **Past sessions.** Your Claude conversations are **auto-saved** (Settings → Auto-save, every 5 minutes by default; 1 / 2 / 5 / 10 / 15 / 30 minutes or Off). The first auto-save names the session itself from your first message plus the date and time, and every later auto-save overwrites that same saved session, so you never have to press anything. **Save session** saves right away (and asks for a name if it has none yet); once saved, a session also updates itself after every reply. **Past sessions** lists them: **Open** (Claude resumes with full memory of it), **Rename** (or click the session title above the chat), **Delete** (click twice). They live on the host PC under `Mills/Archive/` (the folder name is unchanged) and are never committed.
   - The **model dropdown** picks which Claude model answers you (Fable 5.1, Opus 5.5, Sonnet 5.5, Haiku 5.5, or your account's default). It applies from your next message (after the current reply), to every new chat, and survives restarts. Each "Done" line shows which model answered.
   - **My worktree / Shared folder** (top bar) picks where Claude works when you ask it to change Mills itself. **My worktree** (the default) is your own git copy of Mills on the host, `Mills-worktrees/<username>` next to the Mills folder, on branch `work/<username>`, created from `develop` the first time you send a message, so several people can have Claude change Mills at the same time without touching each other's changes. Ask Claude to "merge into develop" when your change is done; going live (develop → main + hub restart) is a separate step that only happens when asked. **Shared folder** is the host's Mills folder itself, the running hub's own checkout that everyone shares. Switching starts a new chat. The host can run `node bridge/worktree.js status | ensure <username> | commit <username> [message] | sync <username> | merge <username>` (from the Mills folder or from inside a worktree; `commit` stages everything uncommitted in that person's worktree so `merge` can take it; `merge` carries work/<username> into develop and `sync` carries develop back into work/<username>; merges use a temporary checkout that is removed afterwards, so develop stays free to check out in the Mills folder); `"worktreeRoot"` in `bridge/config.json` moves the worktrees folder.
   - **Theme** opens 23 UI colour themes plus the Mills default, remembered in that browser.
3. **Chat** is a room shared by every account. Messages are end-to-end encrypted (see Security). The list on the left has **# Everyone** and a **private conversation** with each person (only the two of you can read it). Red numbers count unseen messages per conversation, on the Chat button in the menu and on the Team chat button in Work; the tab title shows the total. Key fingerprints are under **Key fingerprints** at the bottom of that list.
   - **Click a message** to **Reply** (your message shows a quote that jumps back to the original), and on your own messages **Edit** or **Delete** (click twice). Edited messages say "edited"; deleted ones leave a "message deleted" marker. Times are shown in your own browser's time zone (hover for the full date).
   - **Receipts.** Under your messages: "seen alex · unseen sam" — who has looked at that conversation since. Any message's menu shows the same for it.
   - **@mentions.** Type `@` and pick a person (Tab / Enter takes the first match), or write `@username` / `@nickname`. Mentions of you are highlighted.
   - **Sounds.** Three different tones: a normal message, an @mention of you (or a private message to you), and a reply to one of your messages. Each has its own volume slider in Settings. No sound plays for the conversation you are looking at.
   - **Read aloud (optional).** Turn on "Read new chat messages aloud" in Settings and new messages are spoken one after another ("Alex: …", "Alex privately: …", "Alex replied: …") with your browser's built-in voices, so you can keep working and just listen. Settings has speech volume, speed, voice (with ▶ to try them before saving), whether to read every message or only @mentions / private messages / replies to you, and a button to stop and clear the queue. Code blocks and links are not read out; messages in the conversation you are looking at are not read.
   - **Dictation (🗣).** Next to Send in the team chat and in the Claude box in Work. Click it and talk: your words are typed into the box after whatever is already there, so you can stop, fix something, and click again to carry on. It stops by itself after about 3 seconds of silence (or click it again, or start typing). It never sends on its own — press **Send** / **Enter** — with one exception: finish with the words **"send message"** and then pause; the button turns green and the message is sent (without those two words). Speaking again during that pause cancels it. Uses the browser's own speech recognition (Chrome, Edge; not available in Firefox, where the button is hidden). Note: in Chrome and Edge the audio is turned into text by the browser maker's speech service, so dictated speech leaves your computer that way; the resulting text is sent end-to-end encrypted like anything typed.
   - **Voice clips.** Press 🎤 next to Send to record (the browser asks for microphone access the first time; the microphone is switched off again as soon as you stop). Up to 2 minutes; **Send clip** or **Cancel**. Anything typed in the box goes along as a caption, and a clip can be a reply. Clips are encrypted end to end exactly like text and play inline with a player; Settings has a voice clip volume and **Auto-play incoming voice clips**, which plays them one after another in the same queue as read-aloud (the stop button clears both).
   - **Voice / video calls.** **📞 Call** (top of the chat) starts or joins the call of the conversation you are in: # Everyone has one shared call, each private conversation its own two-person call. There is no ringing: when someone is in a call you get a notification (one soft tone, a pop-up you can click to join, and a "… is in a call here — Join" bar in that conversation). Joining uses your microphone (listen-only if you do not allow it); **the camera always starts off** and is switched on and off with **📷** even when the browser already allows it (the camera light goes off when you turn it off). **Mute / Unmute** (or the **M** key when you are not typing) switches your microphone, **Leave** hangs up. Whoever is talking gets a green glowing ring around their tile (you too). Each person's tile has its own **🔊 / 🔇** and volume slider (hover the tile): they only change what you hear, are kept in your browser per person, and multiply with the call volume in Settings; closing the tab or signing out leaves too. While the chat is open (Chat screen, or Team chat in Work with its side list shown) the call sits at the top of the chat's side list; otherwise it is a small window you can drag anywhere, and it snaps to the nearest corner or edge when you let go.
     - **End-to-end encrypted.** Audio and video go straight between the browsers over WebRTC (DTLS-SRTP). The hub only passes on the connection set-up, and those messages are encrypted with the same per-person chat keys, so the hub can neither listen in nor put itself in the middle. Compare key fingerprints once to be sure nobody swapped a key.
     - **Codecs.** Opus for voice (≈32 kb/s, error correction for lossy networks, near-silent when nobody talks); video prefers VP9, then AV1, VP8, H.264. All are decoded by the browser itself. Settings → Video quality: low 320×180 / medium 640×360 (default) / high 1280×720.
     - **Microphone processing** (Settings, used for voice clips and calls): noise suppression (on by default), echo cancellation and automatic level, each switchable; changes apply to a call in progress. Settings also has the call volume.
     - **Networks.** Browsers find each other with a public STUN server (Google's by default: it learns each browser's public IP address, never any audio or video). On very strict networks a direct connection is impossible; the host can then add a TURN relay to `"iceServers"` in `bridge/config.json` (standard WebRTC format; TURN only relays encrypted media). Calls are a mesh (everyone connects to everyone), meant for a small team.
   - **Pop-ups.** While you are in Work, new messages float up in the bottom-right corner and fade away (click one to open it). Turn them off in Settings.
   - **Settings** (main menu, the chat header, and the Work bar): nickname (shown with your messages and usable for @mentions), your colour (16 preset colours that stay distinct from each other and adapt to every theme; "auto" picks one from your username), sound on/off, the three volumes with ▶ to test, pop-ups on/off, and the theme. Nickname and colour are stored on the hub so everyone sees them; the rest follows your account.
   - **Unity (Claude) is in the room too.** She says hi when someone signs in. Otherwise only her own handle calls her: write **`@unity`** (any capitalisation; `@claude` or just "unity" no longer do). Your browser only encrypts a message for her when it contains `@unity` (or is a private message to her), and then sends the **5 messages before it** in that conversation along inside the encryption — so she reads at most the **last 6 messages** and the hub cannot read the rest of the chat. She answers in the room in the lab's Unity persona. A private message to her always gets a private answer that only you receive. It works in the host's Mills folder, so it can also work on Mills itself when asked. The hub won't restart while Claude or anyone else is in the middle of a reply. Set `"roomAgent": false` in `bridge/config.json` to remove it, `"roomAgentModel"` to choose its model, and `"roomAgentName"` to rename it (default Unity).

## Publishing updates

The app is published from `main` (GitHub Pages deploys `web/`). Work follows Git Flow: `feature/<name>` from `develop`, merged `--no-ff` into `develop`, then `develop` into `main`. The Pages workflow fills in the gist owner from the `MILLS_GIST_OWNER` repository variable (Settings → Secrets and variables → Actions → Variables), so no account handle lives in the source. Never commit `auth.json` / `state.json`, `bridge/profiles/`, `bridge/hub-state.json`, `Archive/`, `Chat/`, logs or `.claude/` (all kept out by `.gitignore`).

## Security

- **First sign-in claims an account.** The first browser that signs in to an account becomes the only one allowed into it. To move someone to a new browser, an admin uses **Reset lock** in Admin.
- Passwords are stored on the host PC only, as scrypt hashes. After 5 failed sign-ins for a username, that username is blocked for 15 minutes. Only the GitHub Pages origin may call the hub. The Admin endpoints check the account's `admin` flag on every request.
- **Chat encryption.** Each account has an ECDH P-256 key pair created in its browser. The private key stays in that browser and is also backed up on the hub encrypted with a key derived from the account password (PBKDF2, 310,000 rounds), so it follows the account to a new browser. Every message is encrypted with a fresh AES-256-GCM key, which is wrapped separately for each member. The hub (and its disk, `Mills/Chat/`) only ever holds public keys, the locked backups and ciphertext, and each reader is sent only their own wrapped key. Limits worth knowing: the hub sees your password for a moment when you sign in, so someone who controls the host PC *while you sign in* could unlock your backup; compare fingerprints in the member list once with each other to rule out a swapped key. A password reset done by Admin on someone who then signs in from a new browser starts a fresh key: older messages stay unreadable in that new browser. What the hub can see without reading any message: who sent what when, who a private message is for, whether a message was edited or deleted, and the receipts (how far each person has read each conversation). Deleting a message removes its ciphertext from the hub's disk. **Exception: Claude.** Its private key is kept on the hub (`Mills/Chat/agent-key.json`) so it can read and reply, which means the host PC can read every message sent while Claude is a member.
- Claude can't run shell commands by default. `allowedTools` / `permissionMode` in `bridge/config.json` control that.
